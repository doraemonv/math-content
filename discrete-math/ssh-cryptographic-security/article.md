## 同一条网线上的人，为什么看不见你的命令？

当你执行

```bash
ssh root@服务器地址
```

数据会经过本机网络、路由器、运营商和许多中间设备。它们能够转发数据包，为什么不能直接读出密码、命令和返回结果？另一个更棘手的问题是：攻击者能否冒充服务器，让你把秘密交给错误的人？

“SSH 使用了加密”还不足以回答。一个实际 SSH 连接至少要解决五件不同的事：

1. 双方在公开网络上协商出会话密钥；
2. 客户端确认对面确实是预期服务器；
3. 服务器确认登录者有权限；
4. 后续数据既不能被读懂，也不能被悄悄篡改；
5. 不同用途的密钥彼此分离，一次连接的秘密不随意复用。

这些功能来自不同数学工具。不存在一个叫“SSH 安全定理”的结论，能够无条件保证任何服务器永远不被破解。

## 先把三类身份分开

一条命令里其实出现了三种不同对象：

- **服务器地址**告诉网络把包送到哪里；它通常不是秘密；
- **服务器主机密钥**证明“接收连接的机器是我认识的那台”；
- **用户密钥或密码**证明“发起登录的人有权成为某个用户”。

用户名 `root` 也不是加密密钥。知道 IP 和用户名只相当于知道一扇门在哪里、门牌写了什么，并不自动获得钥匙。但公开入口会持续遭遇扫描和登录尝试，因此仍要减少认证面、及时更新软件并保护私钥。

## 第一层：在被监听时协商同一个秘密

现代 SSH 常见的一类密钥交换是 Curve25519 上的 Diffie–Hellman。先用简化符号看它为什么能得到同一个结果。

公开固定一个群元素 (G)。客户端随机选择临时秘密 (a)，发送

\[
A=aG.
\]

服务器随机选择临时秘密 (b)，发送

\[
B=bG.
\]

客户端计算

\[
K=aB=a(bG)=(ab)G,
\]

服务器计算

\[
K=bA=b(aG)=(ba)G.
\]

因为整数乘法满足 (ab=ba)，双方得到同一个共享秘密 (K)。监听者看得到 (G,A,B)，却需要从 (A=aG) 或 (B=bG) 反求临时秘密，或者直接从公开值求出共享秘密。这对应椭圆曲线离散对数及相关计算困难假设。

[RFC 8731 定义了 SSH 中的 `curve25519-sha256` 和 `curve448-sha512` 密钥交换。][rfc8731] 它还要求检查异常输入，例如共享秘密不能是全零值。这提醒我们：数学结构正确还不够，协议必须验证边界条件。

> **直觉解释：** 双方各自在对方公开值上施加自己的秘密操作，最终落到同一个点。这里的等式解释“为什么相等”；离散对数困难性才解释“旁观者为什么难以得到它”。

## 第二层：共享秘密不能自动证明对方是谁

裸 Diffie–Hellman 会遭遇中间人攻击。攻击者可以分别和客户端、服务器各建立一个共享秘密，再转发和修改两边消息。双方都有加密，但加密对象都是攻击者。

SSH 的关键补丁是：服务器使用长期**主机私钥**，对包含双方握手信息、临时交换值、共享秘密等内容的交换哈希签名。客户端用服务器主机公钥验证签名。[SSH 传输层 RFC 把共享秘密 (K)、交换哈希 (H) 和主机签名组合起来完成服务器认证。][rfc4253]

然而还有一个逻辑问题：客户端怎样知道第一次拿到的主机公钥真属于目标服务器？通常依靠以下方式之一：

- 预先通过可信渠道核对主机密钥指纹；
- 使用管理员分发的 `known_hosts`；
- 使用可信 SSH 证书体系；
- 在首次信任后，把主机密钥记入 `known_hosts`，后续检测变化。

如果第一次连接时不核对指纹，直接接受任何主机密钥，SSH 只能记住“第一次见到的那把钥匙”，不能证明第一次没有中间人。`ssh-keyscan` 也只负责获取主机公钥，官方手册明确说明它本身不能验证公钥真实性，结果应通过带外渠道核对。[OpenSSH `ssh-keyscan` 手册对此有直接警告。][ssh-keyscan]

因此看到

```text
REMOTE HOST IDENTIFICATION HAS CHANGED
```

时，不能为了消除提示就直接删除旧记录并继续。它可能只是服务器重装，也可能意味着 DNS、路由或连接被劫持；应先通过控制台或其他可信渠道核对新指纹。

## 第三层：从一个共享秘密派生多把钥匙

密钥交换得到 (K) 后，SSH 不直接把同一串字节到处使用。协议把 (K)、交换哈希 (H)、会话标识和不同标签送入哈希派生过程，为两个方向生成不同材料，例如：

- 客户端到服务器的加密密钥；
- 服务器到客户端的加密密钥；
- 两个方向各自的完整性密钥或认证状态。

简化表示为

\[
K_{c\to s}=H(K\mathbin\|H_{ex}\mathbin\|C\mathbin\|session),
\]

\[
K_{s\to c}=H(K\mathbin\|H_{ex}\mathbin\|D\mathbin\|session).
\]

标签不同，输出用途便不同。这叫密钥分离：即使底层共享秘密相同，也尽量避免两个方向、两个用途误用同一密钥。RFC 4253 给出了这套派生结构。[协议原文列出了双方的初始向量、加密密钥和完整性密钥。][rfc4253]

## 第四层：为什么既要保密，又要防篡改？

只有加密并不够。攻击者即使看不懂明文，也可能翻转、删除或重放密文片段。安全通道还必须检测修改。

现代组合通常使用经过认证的加密方案，或者将加密与消息认证码正确组合。可以把每个数据包抽象成

\[
(C,T)=\operatorname{EncryptAndAuthenticate}(K,nonce,M,A),

\]

其中 (M) 是命令或输出，(C) 是密文，(T) 是认证标签，(A) 是参与认证但不加密的附加信息。接收方只有在标签验证通过时才接受明文。

这里有两个不同目标：

- **机密性：** 中间人难以从 (C) 得到 (M)；
- **完整性与真实性：** 中间人难以构造会被接受的修改后数据包。

“抓包看到乱码”只说明表面上不像明文，不能单独证明协议安全。算法、密钥、随机数、nonce 使用、认证顺序和实现都必须正确。

## 第五层：服务器怎样确认登录用户？

服务器身份验证完成后，SSH 还要做用户认证。公钥认证的简化过程是：

1. 你的公钥预先放在服务器允许列表中；
2. 客户端用本地私钥对本次会话相关数据签名；
3. 服务器用已登记公钥验证签名；
4. 验证通过说明客户端能够使用私钥，但私钥本身没有通过网络发送。

Ed25519 是 SSH 可使用的签名算法之一。[RFC 8709 规定了 SSH 中 Ed25519/Ed448 公钥和签名的格式。][rfc8709] 数字签名解决的是“证明持有私钥”，不是用用户私钥加密整个终端流量；流量加密使用的是密钥交换后派生的会话密钥。

如果使用密码登录，密码也会在已建立的加密通道内发送，不会以明文暴露给被动监听者。但它仍可能遭遇弱密码猜测、钓鱼、客户端恶意软件和服务器端泄露。高熵公钥认证加上妥善保护的私钥，通常更适合互联网服务器。

## 三个层次的攻击例子

### 被动监听

攻击者只能复制经过的网络包。只要协商使用可靠算法、临时秘密没有泄露、实现正确，他能看到连接时间、IP、包大小等元数据，却难以恢复命令正文。

### 主动中间人

攻击者能拦截并替换包。主机签名与可信主机指纹本应阻止他冒充服务器；但如果用户第一次连接就无条件接受陌生指纹，认证链在最前端出现了缺口。

### 端点已经失守

如果客户端有键盘记录器，命令在加密前就被读取；如果服务器已被入侵，命令在解密后可被读取；如果私钥文件和解锁口令被盗，攻击者可能直接以用户身份登录。SSH 只保护通信通道，不能把不可信端点变成可信端点。

这个反例非常重要：一段通过网络无法解开的密文，并不意味着两端机器安全。

## 什么数学假设在分别工作？

| 环节 | 数学或密码学依据 | 主要目标 |
| --- | --- | --- |
| Curve25519 密钥交换 | 椭圆曲线上的离散对数及相关计算困难 | 协商共享秘密 |
| 主机与用户签名 | 数字签名不可伪造性 | 证明持有私钥 |
| 哈希与密钥派生 | 原像、碰撞等性质及域分离设计 | 绑定握手、派生不同密钥 |
| 对称加密 | 大密钥空间与密码分析安全性 | 隐藏通信内容 |
| MAC 或 AEAD 标签 | 伪造标签在计算上不可行 | 检测篡改 |

这些通常是**条件式保证**：如果困难假设成立、算法选择合理、随机数正确、密钥未泄露、实现无漏洞、用户正确验证身份，那么特定攻击模型下的成功概率极低。

数学证明可以把“攻破整个协议”归约到“攻破某个底层假设”，却不能证明机器没有后门、管理员不会泄露密钥，或未来永远没有新算法。

## 你的 SSH 连接实际使用哪套算法？

SSH 会协商算法，不能只看“我运行了 ssh”就断言一定使用 Curve25519、Ed25519 或某个对称密码。客户端调试输出可以显示实际结果：

```bash
ssh -vv root@服务器地址
```

重点查看输出中的 key exchange、host key、cipher 等字段。`-vv` 会产生较多诊断信息；分享日志前应检查其中的用户名、地址和路径等信息。

查看客户端支持的算法可以使用：

```bash
ssh -Q kex
ssh -Q key
ssh -Q cipher
ssh -Q mac
```

在你有管理权限的服务器上，可用下面的方式查看 sshd 展开后的有效配置：

```bash
sshd -T
```

这不是让人随意复制一份“最强配置”。算法可用性取决于 OpenSSH 版本和客户端兼容需求。IETF 的 SSH 密钥交换建议会随研究与实现变化，例如 RFC 9142 已把旧的 SHA-1 和 1024 位 RSA/DH 强度视为不足，并推荐现代 Curve25519 方案。[RFC 9142 给出了密钥交换方法的更新建议。][rfc9142]

## 怎样理解 root 登录的实际风险？

数学不会因为用户名是 `root` 就变弱，但认证成功后的后果更严重：攻击者一旦取得 root 会直接拥有最高权限。因此保护互联网 SSH 服务通常还需要：

- 使用可靠生成并妥善保管的用户私钥，给私钥设置合适的解锁口令；
- 从可信渠道核对服务器主机指纹，不忽略指纹变化警告；
- 在确认密钥登录和应急访问方式可用后，再评估关闭密码认证；
- 评估禁止 root 直接登录，改为普通管理用户加受控提权；
- 更新 OpenSSH 和操作系统安全补丁；
- 限制允许登录的账号与网络来源，并监控失败尝试；
- 保护客户端、服务器、备份、云平台控制台和 SSH agent。

OpenSSH 的 `sshd_config` 支持 `PubkeyAuthentication`、`PasswordAuthentication`、`PermitRootLogin` 和组合认证等选项。[具体含义应以正在运行版本的官方手册为准。][sshd-config]

配置修改有把自己锁在服务器外的风险。正确流程通常是保留一个已验证的现有会话，先检查配置语法，再从另一个终端测试新连接，最后才结束旧会话。本文解释安全原理，不替代针对具体服务器的变更与回滚方案。

## 前向保密解决的又是什么？

如果密钥交换使用每次连接新生成的临时秘密 (a,b)，会话结束后销毁它们，那么日后服务器长期主机私钥泄露，也不应仅凭旧抓包直接恢复过去的共享秘密。这种目标称为前向保密。

但它有边界：

- 攻击者在会话进行时控制端点，仍能看到明文；
- 临时秘密若被记录或随机数失效，假设不成立；
- 主机私钥泄露后，攻击者可能冒充未来连接，直到密钥被更换并重新建立信任；
- 流量元数据通常不会因内容加密而全部消失。

## 黎曼猜想与 SSH 有直接关系吗？

通常没有。传统有限域 Diffie–Hellman 会使用大素数模数，椭圆曲线也在有限域上定义，但这不表示协议安全依赖黎曼猜想。

黎曼猜想描述 zeta 函数零点与质数分布误差。SSH 的直接安全链则是具体密钥交换、签名、哈希与对称密码的安全假设。证明黎曼猜想不会自动泄露 SSH 私钥，也不会自动解出 Curve25519 离散对数。

这和 Bitcoin 的情况相似：数论提供了语言和结构，但协议依赖的是更具体的计算困难问题。可继续阅读[Bitcoin 私钥为什么难以破解](/articles/bitcoin-key-security)。

## 常见误解

- **“端口 22 被扫描就说明加密被破解。”** 扫描只发现服务入口；认证能否被绕过是另一个问题。
- **“有小锁或看到密文就不会被中间人攻击。”** 如果未验证主机密钥，你可能与攻击者建立了一条加密通道。
- **“公钥认证会把私钥发送给服务器。”** 正常协议发送公钥和签名证明，私钥留在客户端。
- **“禁用密码后服务器绝对安全。”** 它减少一类攻击面，但私钥窃取、软件漏洞、错误授权和端点失守仍可能发生。
- **“SSH 加密能隐藏服务器 IP 和连接时间。”** 网络仍需知道目的地址，中间设备也能观察元数据。
- **“数学证明保证不会被黑。”** 证明只覆盖模型中的算法性质，不覆盖全部系统现实。

## 练习

1. 不使用“因为加密了”，用自己的语言说明 SSH 为什么需要密钥交换、主机认证和用户认证三个不同步骤。
2. 推导为什么客户端的 (aB) 与服务器的 (bA) 相等。
3. 如果取消主机签名和指纹验证，只保留 Diffie–Hellman，会出现什么攻击？
4. 为什么服务器地址和用户名公开不等于私钥公开？又为什么公开入口仍要防护？
5. 解释“加密但不认证”可能留下什么问题。
6. 如果攻击者已经控制客户端，SSH 通道的机密性还能保护键盘输入吗？
7. 主机长期私钥在一年后泄露。什么条件下，攻击者仍难以解密一年前保存的流量？
8. 看到主机指纹变化时，为什么“删掉 known_hosts 旧行再连接”不是完整的安全处理？
9. 证明黎曼猜想是否等于破解 Curve25519？给出准确而不过度承诺的回答。

## 练习答案

### 题 1
密钥交换让公开网络上的双方得到会话秘密；主机认证防止把秘密交给冒充服务器的人；用户认证让服务器只接受有权限的登录者。任一步缺失都不能得到完整的安全远程登录。

### 题 2
客户端得到 (aB=a(bG)=(ab)G)，服务器得到 (bA=b(aG)=(ba)G)。因为 (ab=ba)，两者相同。

### 题 3
主动中间人可与客户端和服务器分别完成密钥交换，建立两条不同的加密通道，再居中读取和修改转发内容。

### 题 4
地址只负责路由，用户名只指定目标账号；私钥是另外生成和保存的秘密。公开入口不会直接泄露私钥，但会让攻击者找到可持续尝试认证和探测漏洞的服务。

### 题 5
攻击者可能翻转、替换或重放密文，使接收方处理被修改的数据。完整性标签或经过认证的加密用于检测这种行为。

### 题 6
不能。键盘记录器可在字符进入 SSH 加密前读取它；终端被控制时，攻击者也可能读取屏幕或进程内存。

### 题 7
需要使用提供前向保密的临时密钥交换，临时秘密可靠随机、未被保存或泄露，算法与实现未被攻破。仅有旧抓包和后来泄露的长期主机私钥应不足以恢复旧会话密钥。

### 题 8
应先判断是合法重装、密钥轮换还是中间人攻击，并通过控制台、管理员或其他可信渠道核对新指纹。直接删除记录会同时删除原本用于报警的信任锚。

### 题 9
不等于。目前没有已知结论把黎曼猜想的证明自动转化为 Curve25519 离散对数的高效算法。准确说法是“没有这种已知直接推论”，而不是声称已经证明两者在所有未来数学中绝无关系。

## 如果你真的理解了

- 为什么 Diffie–Hellman 的等式说明双方能得到同一秘密，却没有单独解决身份认证？
- 为什么主机指纹第一次如何获得，是整条信任链的一部分？
- 你能区分主机密钥、用户密钥和会话密钥吗？
- 哪些攻击是数学困难性阻止的，哪些攻击必须靠系统配置和运维阻止？
